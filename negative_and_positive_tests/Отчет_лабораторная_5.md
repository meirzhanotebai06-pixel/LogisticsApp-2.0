## Цель и границы проверки

Проверены функции `validateEmailDetailed`, `isValidPassword`, `isValidPhone`, `isValidName` из `LogisticsApp/Services/AuthValidation.swift`. Приложение вызывает этот же файл через `AuthService.swift`. Набор из 20 XCTest находится в `Tests/ValidationCoreTests/AuthValidationTests.swift`; локальный Swift Package в этой папке подключает производственный файл через символическую ссылку. Команда запуска из корня проекта: `swift test --package-path Лабораторная_5`. Проверяются реальные функции валидации без Firebase.

Первый запуск: 17 PASS, 3 FAIL (`first_test_run.log`). После исправления трёх дефектов повторный запуск: **20 PASS, 0 FAIL** (`final_test_run.log`). UI-проверки Firebase не входили в этот набор.

После исправлений проект успешно собран для iPhone 17 Pro (iOS 26.3), установлен и запущен в симуляторе. Снимок актуальной сборки `screenshots/02-updated-build.png` показывает экран входа с неактивной кнопкой при пустых полях. Снимок `screenshots/01-driver-screen.png` относится к ранее установленной версии и сохранён для сравнения.

## Требования и пять сценариев

| ID | Требование по текущей реализации | Сценарий |
|---|---|---|
| R1 | Email имеет допустимый формат и длину не более 100 символов | S1: корректные варианты email принимаются |
| R2 | Некорректный email отклоняется | S2: пустой адрес, отсутствие @/домена, неверные разделители |
| R3 | Пароль содержит только латинские буквы и цифры; пустое значение не принимается формой регистрации | S3: допустимый и недопустимый пароль |
| R4 | Телефон содержит ровно 11 цифр; посторонние буквы не допускаются | S4: формат и граница длины телефона |
| R5 | Имя состоит из букв, допускает два слова, длина 2–50 символов | S5: допустимое и слишком короткое имя |

Предусловие каждого кейса: локальный Swift доступен, исходный файл `AuthService.swift` присутствует, Firebase не вызывается. Шаги: (1) запустить `swift test --package-path Лабораторная_5` из корня проекта; (2) найти метод с ID в протоколе XCTest; (3) сравнить результат с `XCTAssert`. Значение `true` означает принятие данных функцией, `false` — отказ. Приоритет P1 — критичная проверка формы; P2 — обычная проверка. Severity указан для случая нарушения ожидания.

| ID | Связанный тест | Шаги воспроизведения | Ожидаемое / фактическое | Вероятная причина | Severity |

| D-01 | N05 | Передать `a@b..kz` в `validateEmailDetailed` | отказ / принят | Проверяются сегменты и итоговый regex, но последовательные точки домена не запрещены | Major |
| D-02 | N07 | Передать пустую строку в `isValidPassword` | отказ / принят | Regex `*` разрешает ноль символов. UI отдельно запрещает пустое поле | Major |
| D-03 | N09 | Передать `abc77001234567` в `isValidPhone` | отказ / принят | Функция удаляет все нецифровые символы, затем проверяет лишь число цифр | Major |

**Повторный тест:** после исправления `AuthValidation.swift` весь набор XCTest запущен повторно. N05, N07 и N09 получили PASS. Проверка экранов регистрации/входа и Firebase остаётся отдельной задачей.
